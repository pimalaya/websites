# The packages install page joins the family

pkg.pimalaya.org's install page moves here as sites/pkg, on the shared theme, nav (`packages` tag) and footer, prerendered JavaScript-free. The hub of pimalaya/packages builds it on every run from this repository's master, fills its `@CLIS@`, `@APT@`, `@DNF@`, `@BREW@` and `@FINGERPRINT@` placeholders and deploys it with the package repositories; no `_pkg` repository, since one Pages artifact must carry both.

- sites/pkg: App.tsx (masthead, tools, APT, DNF, Homebrew and signing key sections), App.css (narrow column, tool cards with a version pill, the blog's dark code surface), prerender.js, favicon.
- Root `dev:pkg`, `build:pkg`, `preview:pkg`; flake `packages.pkg`. The flake's npmDepsHash was already stale at HEAD; refreshed for the new lockfile, and www, blog and pkg all build with `nix build`.
- README and the workspace spec no longer describe a pending cutover: www and blog deploy through the Publish workflows of pimalaya/_www and pimalaya/_blog (the renamed standalone repositories), pkg through the packages hub.
- Checked: the hub's linux-build run locally with a throwaway key against sites/pkg/dist, no placeholder left, the APT heredoc's `&` and `<` escaped, screenshots in light, dark and phone widths. Not live until both repositories are pushed and the hub runs.

Capabilities moved: pkg-site (added), workspace (Workspace layout, One toolchain, Migrated sites, Deployment, modified).
